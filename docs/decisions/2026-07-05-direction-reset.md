# 토스 과제 방향 리셋

## 상태

활성 결정. 2026년 7월 5일부터 이전에 합의했던 문제 정의, 문제 상황, 솔루션, 제출 답변 초안, 프로토타입 방향은 새 작업의 기준으로 사용하지 않는다.

## 배경

이전까지는 회의 일정 조율을 `후보 시간 판단 카드`, `요약 신호`, `개인 사유 비공개`, `양보 가능 범위`, `합의 가능성` 중심으로 풀었다.

이 방향은 안정적이었지만, 충분히 독창적인 문제 접근인지에 대한 의문이 생겼다. 또한 처음부터 다시 보면 더 본질적이거나 예상 밖의 문제를 발견할 가능성이 있다.

따라서 지금부터는 기존 방향을 보강하지 않고, 문제 발견 단계부터 다시 시작한다.

## 폐기하는 것

다음 항목은 새 방향의 전제가 아니다.

- `후보 시간 판단 카드`를 중심 컴포넌트로 둔다는 전제
- `요약 신호`와 `개인 사유 비공개`가 핵심 솔루션이라는 전제
- `양보 가능 범위`와 `합의 가능성`을 핵심 문제로 본다는 전제
- Scheduler를 반드시 주인공으로 둔다는 전제
- 기존 1번 답변 초안
- 기존 프로토타입을 발전시키는 접근

## 유지하는 것

아래 자료는 새 방향의 전제가 아니라 참고 기록으로만 유지한다.

- 공식 과제 브리프 분석
- 캘린더/업무툴 화면 관찰 기록
- Mobbin 등 레퍼런스 조사
- 기존 아이디어의 장단점 분석
- 이전 답변 초안과 플로우 문서

삭제하지 않는 이유는, 이후 새로운 방향과 비교하거나 포기한 범위를 설명할 때 참고할 수 있기 때문이다.

## 새 접근 원칙

### 1. 솔루션을 먼저 정하지 않는다

새 작업에서는 카드, 투표, AI, 에이전트, 캘린더 오버레이 같은 해결 방식을 먼저 정하지 않는다.

먼저 과제에서 주어진 상황을 다시 읽고, 그 안에서 사용자가 실제로 겪는 문제 후보를 최대한 많이 뽑는다.

### 2. `일정 조율 = 시간 찾기`라는 프레임을 의심한다

회의 일정을 잡는 경험이 꼭 시간 후보 비교의 문제인지 다시 검토한다.

가능한 다른 문제 층위:

- 회의 자체가 필요한지 판단하는 문제
- 6명을 모으는 기준을 정하는 문제
- 참석자 역할을 정하는 문제
- 회의 전 준비 수준을 맞추는 문제
- 확정 이후 변경과 책임을 다루는 문제
- 바쁜 사람들의 주의와 에너지를 배분하는 문제

### 3. 공식 과제 상황을 다시 분해한다

토스가 준 회의 상황, 조건, 질문 문구, 평가 포인트를 다시 확인한다. 우리가 상상한 문제가 아니라 과제 안에서 도출 가능한 문제여야 한다.

### 4. 문제 후보는 넓게, 최종 선택은 좁게 한다

처음에는 많이 펼치고, 최종 제출에서는 하나의 핵심 문제만 선택한다.

후보 문제를 비교할 기준:

- 공식 과제 조건에서 자연스럽게 도출되는가
- 다른 지원자가 쉽게 떠올릴 가능성이 낮은가
- 700자 안에 선명하게 설명 가능한가
- 화면으로 증명 가능한가
- 2번과 3번 답변에서 논리적으로 이어지는가

### 5. 프로토타입은 나중에 정한다

현재 프로토타입은 일단 보류한다. 새로운 문제정의가 정해지기 전까지 기존 프로토타입을 수정하지 않는다.

## 다음 작업

1. 공식 과제 브리프와 주어진 회의 상황을 다시 확인한다.
2. 기존 방향을 제외하고 문제 후보를 최소 10개 이상 도출한다.
3. 각 문제 후보를 사용자, 상황, 왜 문제인지, 기존 캘린더가 못 푸는 이유로 정리한다.
4. 문제 후보를 평가 기준으로 비교한다.
5. 상위 2~3개 문제에 대해 1번 답변 초안을 각각 써본다.
6. 그중 가장 강한 문제 하나를 선택한 뒤에야 솔루션을 설계한다.

## 열어둘 질문

- 토스 과제에서 실제로 주어진 회의 상황은 무엇이었나?
- 사용자는 반드시 회의 주최자인가, 아니면 참석자나 팀 전체일 수도 있는가?
- 회의 일정 조율에서 `시간`보다 더 큰 문제가 있는가?
- 회의 일정 잡기 전후의 맥락까지 다뤄도 과제 범위 안에 들어오는가?
- 다른 지원자들이 가장 많이 선택할 문제정의는 무엇일까?

# 토스 PD 챌린지 제품 완성안

## 목적

이 문서는 1번 문제 정의와 2번 해결안을 실제 제품 구조로 연결하기 위한 문서다.

핵심 목표는 “좋은 회의 시간”을 제품이 어떤 기준으로 판단하고, 사용자에게 어떤 정보와 선택지로 노출하는지 명확히 정리하는 것이다.

기존 캘린더 서비스나 네이버웍스 같은 실제 제품은 내부 기준점으로만 참고한다. 제출 답변에서는 특정 서비스를 직접 언급하지 않고, 기존 캘린더 UX가 일반적으로 해결하는 영역과 아직 남는 문제를 분리해서 설명한다.

## 제품 한 문장

회의 목적에 따라 후보 시간을 평가하고, 주최자가 왜 이 시간이 좋은 선택인지 이해한 뒤 확정할 수 있게 돕는 일정 조율 캘린더.

## 문제의 중심

기존 캘린더는 가능한 시간대를 찾는 데 도움을 준다. 사람별 일정을 겹쳐 보고, 빈 시간을 확인하고, 회의실 같은 리소스를 함께 예약하는 수준은 이미 많은 업무용 캘린더가 제공한다.

따라서 이 과제에서 해결해야 할 문제는 “빈 시간을 못 찾는다”가 아니다.

진짜 문제는 다음이다.

> 사용자는 빈 시간 후보를 찾은 뒤에도, 그 후보가 회의 목적에 맞는 좋은 시간인지 판단해야 한다. 하지만 기존 캘린더는 후보 시간의 품질을 판단할 기준을 충분히 제공하지 않는다.

이때 좋은 시간은 모두가 비어 있는 시간이 아니다. 좋은 시간은 회의 목적을 덜 해치고, 참석자가 실제로 참여하기 좋은 맥락을 갖고 있으며, 주최자가 선택 이유를 설명할 수 있는 시간이다.

## 좋은 시간의 정의

이 제품에서 좋은 시간은 네 가지 조건을 통과한 시간이다.

### 1. 회의가 성립한다

가장 먼저 확인하는 최소 조건이다.

- 필수 참석자가 참석 가능하다.
- 회의 길이를 확보할 수 있다.
- 회의가 잡혀야 하는 기간 안에 있다.
- 필요한 회의실, 화상 회의, 장비가 가능하다.

이 조건은 점수화하지 않는다. 필수 참석자가 불가능하거나 필요한 설비가 없으면 그 시간은 기본 후보에서 제외한다.

### 2. 회의 목적에 맞다

같은 1시간 회의라도 목적에 따라 좋은 시간의 기준은 달라진다.

- 빠른 결정: 가능한 빠르게 잡을 수 있고, 결정에 필요한 사람이 준비 없이도 참석할 수 있는 시간
- 깊은 논의: 점심 직후나 퇴근 직전이 아니고, 앞뒤 일정이 붙어 있지 않아 집중하기 좋은 시간
- 공유/싱크: 많은 사람이 부담 없이 들어올 수 있고, 업무 흐름을 크게 끊지 않는 시간
- 긴급 조율: 모든 선호를 만족시키기보다 핵심 조건을 지키면서 가장 빠르게 모일 수 있는 시간

제품은 회의 목적을 먼저 묻고, 목적에 따라 후보 시간의 평가 기준을 바꾼다.

### 3. 시간의 질이 낮지 않다

캘린더상 비어 있어도 좋은 시간이 아닐 수 있다. 그래서 제품은 다음 신호를 후보 시간의 품질로 반영한다.

- 점심 직후
- 출근 직후나 퇴근 직전
- 바로 앞뒤에 다른 회의가 붙어 있는 시간
- 같은 날 회의가 과도하게 몰린 시간
- 외근이나 이동 가능성이 높은 요일
- 집중 업무 시간이 깨질 가능성이 높은 시간

이 신호들은 무조건 제외 조건이 아니다. 다만 후보 카드에서 “왜 약한 후보인지” 또는 “무엇을 감수해야 하는지”로 표시한다.

### 4. 불확실성이 낮다

`한가함`, `hold`, 비공개 일정, 외근 가능성처럼 캘린더만으로 해석이 어려운 상태가 있다. 제품은 이를 단순히 가능/불가능으로 눌러버리지 않고, 확인이 필요한 신호로 다룬다.

예를 들어 어떤 후보가 전체적으로 좋지만 한 명의 hold 일정 때문에 불확실하다면, 그 후보를 버리지 않는다. 대신 `확인 필요` 후보로 보여주고, 해당 사람에게만 짧은 확인을 요청하게 한다.

## 사용자가 입력하는 정보

사용자에게 긴 폼을 요구하지 않는다. 회의 생성 흐름 안에서 필요한 판단 기준만 가볍게 받는다.

### 회의 기본 정보

- 회의 제목
- 회의 길이
- 잡아야 하는 기간
- 참석자
- 회의실 또는 화상 회의 필요 여부

### 회의 목적

회의 목적은 좋은 시간 기준을 정하는 핵심 입력이다.

사용자는 다음 중 하나를 고른다.

- 결정하기
- 깊게 논의하기
- 빠르게 공유하기
- 긴급하게 모이기

제품은 회의 제목과 참석자 구성을 보고 기본값을 제안할 수 있지만, 최종 선택은 사용자가 한다.

### 시간 선호

회의 목적을 고르면 기본 선호가 자동으로 켜진다. 사용자는 필요하면 수정할 수 있다.

- 점심 직후 피하기
- 퇴근 직전 피하기
- 앞뒤 15분 여유 두기
- 외근 많은 요일 낮은 우선순위
- 업무 시간 안에서만 찾기
- 모두 가능한 시간만 보기

여기서 중요한 점은 선호를 더 많이 입력하게 만드는 것이 아니다. 제품이 기본 기준을 먼저 세우고, 사용자는 다르게 판단하고 싶을 때만 조정한다.

## 시스템이 가져오는 정보

제품은 기존 캘린더에서 다음 정보를 가져온다.

- 참석자의 free/busy 상태
- 바쁨, 한가함, hold, 비공개 일정 상태
- 앞뒤 일정 간격
- 하루 안의 회의 밀도
- 반복적으로 외근이 많은 요일 또는 위치 신호
- 업무 시간
- 회의실, 화상 회의, 설비 가능 여부

개인 일정 제목이나 상세 사유는 기본적으로 노출하지 않는다. 주최자에게 필요한 것은 “왜 불확실한가”가 아니라 “이 후보를 확정해도 되는가”이기 때문이다.

## 후보 시간 생성 방식

후보 시간은 세 단계로 만들어진다.

### 1. 통과 조건으로 후보를 좁힌다

먼저 회의가 성립하지 않는 시간은 제외한다.

- 필수 참석자가 불가능한 시간
- 회의 길이를 확보할 수 없는 시간
- 필요한 설비가 없는 시간
- 지정 기간 밖의 시간

### 2. 목적별 기준으로 후보를 평가한다

남은 후보는 회의 목적에 따라 다르게 정렬한다.

예를 들어 `깊게 논의하기` 회의라면 다음 기준이 중요해진다.

- 점심 직후가 아닌가
- 앞뒤 회의와 충분히 떨어져 있는가
- 외근이나 이동 맥락이 적은가
- 회의 전 준비 시간이 있는가

반대로 `긴급하게 모이기` 회의라면 다음 기준이 더 중요해진다.

- 가장 빨리 잡을 수 있는가
- 핵심 조건을 만족하는가
- 추가 확인 없이 바로 확정할 수 있는가

### 3. 후보를 선택 가능한 묶음으로 보여준다

제품은 모든 후보를 하나의 긴 리스트로 보여주지 않는다. 사용자가 판단하기 쉬운 묶음으로 나눈다.

- 추천: 회의 목적과 시간 품질이 가장 잘 맞는 후보
- 빠른 확정: 지금 바로 잡기 쉬운 후보
- 집중 우선: 앞뒤 여유와 시간대 품질이 좋은 후보
- 모두 가능: 기존 캘린더식으로 모든 참석자가 가능한 후보
- 확인 필요: 좋은 후보지만 hold, 한가함, 외근 신호 때문에 짧은 확인이 필요한 후보

## 핵심 화면 구조

### 화면 1. 일정 만들기

일정 만들기 화면의 왼쪽은 기존 캘린더처럼 기본 정보를 입력한다. 다만 참석자 입력 아래에 `회의 목적`과 `좋은 시간 기준`이 추가된다.

구성:

- 제목
- 시간 또는 `좋은 시간 찾기`
- 참석자
- 필수 참석자 표시
- 회의 목적 선택
- 좋은 시간 기준
- 회의실/화상 회의

사용자가 `좋은 시간 찾기`를 선택하면 오른쪽 패널이 열린다.

### 화면 2. 좋은 시간 기준 패널

이 패널은 사용자가 제품의 판단 기준을 이해하고 조정하는 곳이다.

예시:

```text
회의 목적
[결정하기] [깊게 논의하기] [빠르게 공유하기] [긴급하게 모이기]

좋은 시간 기준
ON  점심 직후 피하기
ON  앞뒤 15분 여유 두기
ON  외근 많은 요일 낮은 우선순위
ON  업무 시간 안에서만 찾기
OFF 모두 가능한 시간만 보기
```

이 화면의 역할은 사용자가 알고리즘을 믿게 만드는 것이 아니다. 제품이 무엇을 좋은 시간으로 보고 있는지 사용자가 볼 수 있게 만드는 것이다.

### 화면 3. 후보 시간 보드

추천 시간은 파란 칩만 나열하지 않는다. 각 후보를 짧은 카드로 보여준다.

카드 구성:

```text
7.2 목 10:00-11:00
추천: 깊은 논의에 가장 적합

충족
- 필수 참석자 가능
- 회의실 가능
- 점심 직후 아님

좋은 점
- 앞뒤 30분 이상 여유
- 외근 신호 없음
- 회의 전날까지 준비 시간 있음

확인할 점
- 선택 참석자 1명은 다른 일정과 가까움

[이 시간으로 확정] [비교하기]
```

중요한 것은 후보가 왜 좋은지와 무엇을 감수해야 하는지를 동시에 보여주는 것이다.

### 화면 4. 후보 비교

사용자가 두세 개 후보를 비교할 수 있다.

예시:

| 후보 | 판단 | 이유 |
| --- | --- | --- |
| 7.2 목 10:00 | 추천 | 집중 시간대, 앞뒤 여유, 외근 신호 없음 |
| 7.1 수 13:00 | 약함 | 점심 직후이고 앞 일정과 가까움 |
| 7.3 금 16:00 | 빠른 확정 | 바로 잡을 수 있지만 퇴근 직전에 가까움 |

비교 화면은 제품이 대신 결정하는 곳이 아니다. 주최자가 후보 간 차이를 이해하고 직접 선택하는 곳이다.

### 화면 5. 확인 요청

좋은 후보인데 불확실성이 남아 있으면 전체 참석자에게 다시 묻지 않는다. 필요한 사람에게만 확인한다.

확인 요청 예시:

```text
7.2 목 10:00 회의 참석 가능할까요?
이 시간은 현재 캘린더상 확정 일정은 없지만 확인이 필요한 상태예요.

[가능] [어려움] [사전 의견 전달 가능]
```

참석자는 자신의 상세 일정을 공개하지 않아도 된다. 주최자는 결정에 필요한 최소 신호만 받는다.

### 화면 6. 확정 전 요약

주최자가 시간을 선택하면 확정 전 요약을 보여준다.

```text
7.2 목 10:00로 잡을까요?

이 시간이 좋은 이유
- 필수 참석자가 모두 가능해요.
- 점심 직후와 퇴근 직전을 피했어요.
- 앞뒤 일정 여유가 있어 깊은 논의에 적합해요.
- 회의실 15F_A1을 예약할 수 있어요.

알아둘 점
- 선택 참석자 1명은 사후 공유가 더 적합해요.

[확정하고 초대 보내기]
```

이 화면에서 사용자는 “왜 이 시간인가”를 마지막으로 확인한다.

### 화면 7. 참석자에게 공유되는 결정 요약

확정 후 참석자에게는 너무 많은 내부 판단을 보여주지 않는다. 짧은 요약만 공유한다.

예시:

```text
7.2 목 10:00로 회의가 잡혔어요.
필수 참석자가 모두 가능하고, 점심 직후를 피했으며, 앞뒤 일정 여유가 있어 논의에 적합한 시간이에요.
```

이 문장은 주최자의 반복 설명을 줄이고, 참석자가 자신의 조건이 무시되었다고 느끼는 일을 줄인다.

## 사용자가 받는 선택지

제품은 사용자에게 한 가지 정답만 던지지 않는다.

주요 선택지는 다음이다.

- 추천 시간으로 확정한다.
- 빠른 확정 후보를 선택한다.
- 집중 우선 후보를 선택한다.
- 모두 가능한 시간만 본다.
- 확인 필요 후보에 대해 특정 사람에게만 확인 요청을 보낸다.
- 좋은 시간 기준을 조정한다.
- 조건을 완화해서 후보를 다시 찾는다.

이 선택지들이 중요한 이유는 일정 조율에 정답이 없기 때문이다. 제품은 사용자를 대신해서 결정하지 않고, 사용자가 좋은 결정을 내릴 수 있는 구조를 제공한다.

## 후보가 없을 때의 처리

좋은 후보가 없을 때는 빈 화면을 보여주지 않는다. 어떤 조건을 완화하면 후보가 생기는지 보여준다.

예시:

```text
현재 기준으로 확정 가능한 시간이 없어요.

조건을 바꾸면 후보가 생겨요.
- 점심 직후 피하기를 끄면 2개
- 앞뒤 15분 여유를 끄면 3개
- 회의 길이를 45분으로 줄이면 5개
- 다음 주 월요일까지 넓히면 4개
```

이 화면의 목적은 사용자가 “왜 시간이 없는지”를 이해하고, 어떤 기준을 포기할지 직접 선택하게 하는 것이다.

## 정보 노출 원칙

### 주최자에게 보여주는 것

- 후보 시간이 왜 추천되었는지
- 어떤 기준을 충족했는지
- 어떤 기준이 약한지
- 어떤 확인이 필요한지
- 확정하면 참석자에게 어떤 요약이 공유되는지

### 주최자에게 보여주지 않는 것

- 참석자의 비공개 일정 제목
- 개인 일정의 상세 사유
- 불필요하게 민감한 선호 이유
- 선택 참석자를 배제하거나 문제처럼 보이게 하는 표현

### 참석자에게 보여주는 것

- 회의 시간
- 필요한 경우 짧은 확인 요청
- 확정 후 간단한 결정 이유

### 참석자에게 보여주지 않는 것

- 다른 사람의 상세 일정
- 자신이 어떤 후보에서 낮은 점수 요인이 되었는지
- 불필요한 비교표

## 이 제품이 기존 캘린더보다 나은 지점

기존 캘린더는 raw availability, 즉 가능한 시간의 재료를 잘 보여준다.

이 제품은 그 재료를 decision-ready candidate, 즉 결정 가능한 후보로 바꾼다.

차이는 다음과 같다.

- 기존 캘린더: 언제 비어 있는가
- 이 제품: 왜 이 시간이 이 회의에 적합한가
- 기존 캘린더: 후보 시간이 많다
- 이 제품: 후보 간 차이를 이해할 수 있다
- 기존 캘린더: 애매하면 다시 물어본다
- 이 제품: 필요한 사람에게 필요한 질문만 한다
- 기존 캘린더: 확정 후 이유가 남지 않는다
- 이 제품: 선택 이유가 짧게 공유된다

## 과제 답변으로 연결되는 방식

### 1번 답변에서 말할 문제

사용자의 문제는 빈 시간 후보를 찾지 못하는 것이 아니다. 기존 캘린더는 가능한 시간대를 찾는 데 이미 도움을 준다.

문제는 후보 시간이 생긴 뒤에도, 그 시간이 회의 목적에 맞는 좋은 선택인지 판단할 기준이 부족하다는 점이다. 사용자는 캘린더의 빈칸, 점심 직후 같은 선호, 외근 같은 맥락, hold나 한가함 같은 불확실성을 머릿속에서 해석해야 한다.

### 2번 답변에서 말할 해결

회의 목적을 먼저 받고, 목적에 따라 좋은 시간 기준을 자동으로 세운다. 후보 시간은 단순 시간 칩이 아니라 추천 이유, 약한 점, 확인할 점이 있는 카드로 보여준다. 애매한 후보는 전체 재투표가 아니라 필요한 사람에게만 확인하고, 확정 후에는 짧은 결정 요약을 공유한다.

### 3번 답변에서 말할 의사결정

의도적으로 포기한 범위가 있다.

- 모든 일정을 더 자세히 보여주는 방향은 포기했다.
- AI가 알아서 시간을 정해주는 방식은 포기했다.
- 참석자 중요도를 복잡한 점수로 계산하는 방식은 포기했다.
- 대신 회의 목적별 판단 기준을 드러내고, 사용자가 기준을 조정하며 결정하게 했다.

## 최종 제품 원칙

- 빈 시간을 더 많이 보여주는 것이 아니라, 좋은 시간을 판단할 수 있게 한다.
- 필수 조건은 통과 기준이고, 시간 품질은 비교 기준이다.
- 후보 시간은 점수보다 이유로 설명한다.
- 불확실성은 전체 재조율이 아니라 타깃 확인으로 줄인다.
- 개인 일정의 상세 정보는 숨기고, 결정에 필요한 신호만 노출한다.
- 최종 결정은 제품이 대신하지 않고, 사용자가 납득 가능한 근거를 보고 내린다.

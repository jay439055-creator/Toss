# 백지 재접근 리서치 계획

## 목적

토스 Product Designer Challenge 과제를 기존 문제정의와 솔루션에서 분리해 다시 접근한다. 목표는 더 독창적이면서도 공식 과제 안에서 설득 가능한 핵심 문제를 새로 찾는 것이다.

## 현재 아는 것

- 과제는 캘린더/회의 일정 조율 경험과 관련되어 있다.
- 제출 질문은 문제 발견, 해결 방법, 의사결정 이유를 묻는다.
- 1번 답변은 최대 700자이며, 문제를 넓게 나열하기보다 핵심 문제 하나를 선명하게 잡아야 한다.
- 기존 방향은 안정적이지만, 다른 지원자도 도달할 수 있는 문제일 수 있다.

## 의도적으로 보류할 가정

아래 가정은 당분간 사용하지 않는다.

- 핵심 사용자는 반드시 일정 주최자다.
- 핵심 문제는 가능한 시간 중 좋은 후보를 고르는 것이다.
- 개인 사유 비공개가 가장 중요한 문제다.
- 후보 카드가 중심 솔루션이어야 한다.
- 회의 일정 조율은 캘린더 안에서만 해결해야 한다.
- AI나 에이전트가 있어야 차별화된다.

## 모르는 것

- 공식 과제에서 정확히 어떤 회의 상황과 조건이 주어졌는가
- 토스가 이 과제에서 가장 보고 싶어 하는 문제정의의 깊이는 어디까지인가
- 사용자의 실제 고통이 일정 전, 일정 중, 일정 후 중 어디에 있는가
- 기존 캘린더 서비스가 놓치는 가장 근본적인 UX 공백은 무엇인가
- 화면으로 가장 설득력 있게 증명할 수 있는 문제는 무엇인가

## 리서치 질문

1. 공식 과제의 회의 상황은 어떤 제약과 갈등을 내포하고 있는가?
2. 회의 일정 조율에서 사용자가 실제로 실패하는 순간은 언제인가?
3. 기존 캘린더가 제공하는 정보와 사용자가 결정을 위해 필요한 정보 사이에는 어떤 차이가 있는가?
4. 일정 조율을 시간 선택이 아닌 다른 문제로 정의할 수 있는가?
5. 다른 지원자들이 많이 선택할 법한 문제정의와 우리가 피해야 할 평범한 접근은 무엇인가?

## 방법

### 1. 과제 브리프 재분해

공식 공고와 과제 질문을 다시 읽고, 조건과 단서를 문장 단위로 분해한다.

산출물:

- 공식 조건 목록
- 과제에서 직접 도출 가능한 문제 후보
- 과제 밖으로 벗어날 위험이 있는 해석

### 2. 회의 일정 조율 여정 재구성

회의 일정을 잡는 과정을 시간순으로 다시 나눈다.

예상 단계:

- 회의 필요성 발생
- 누구를 모아야 하는지 판단
- 참석자 역할과 필수성을 정함
- 후보 시간 탐색
- 일정 제안
- 반응 수집
- 확정
- 변경/불참/사후 공유

산출물:

- 단계별 사용자 행동
- 단계별 감정과 실패 지점
- 캘린더가 개입하는 지점과 개입하지 못하는 지점

### 3. 문제 후보 발산

기존 방향을 제외하고 최소 10개 문제 후보를 만든다.

각 후보는 다음 형식으로 작성한다.

- 문제 이름
- 사용자는 누구인가
- 어떤 상황에서 발생하는가
- 왜 문제인가
- 기존 캘린더가 왜 못 푸는가
- 화면으로 어떻게 증명할 수 있는가

### 4. 문제 후보 평가

후보를 다음 기준으로 평가한다.

| 기준 | 설명 |
| --- | --- |
| 과제 적합성 | 공식 조건에서 자연스럽게 도출되는가 |
| 차별성 | 다른 지원자가 쉽게 떠올리지 않을 가능성이 있는가 |
| 설명력 | 700자 안에 선명하게 말할 수 있는가 |
| 화면화 가능성 | 프로토타입으로 증명 가능한가 |
| 의사결정 깊이 | 왜 이 방식인지 3번 답변에서 설명할 거리가 있는가 |

### 5. 상위 문제 2~3개 압축

상위 후보마다 1번 답변 초안을 써본다. 초안으로 써봤을 때 가장 선명한 문제를 우선 검토한다.

## 예상 산출물

- 새 문제 후보 리스트
- 문제 후보 평가표
- 상위 2~3개 문제정의 초안
- 최종 문제정의 후보
- 이후 솔루션 설계를 위한 플로우 방향

## 이번 리셋의 성공 기준

- 기존 후보 시간 판단 카드 방향으로 자동 회귀하지 않는다.
- 적어도 하나는 기존 방향과 완전히 다른 문제정의를 찾는다.
- 최종 후보가 1번, 2번, 3번 답변으로 자연스럽게 이어진다.
- 프로토타입을 만들기 전에 문제정의가 먼저 납득된다.
